## 2. 业务模型：1 对 1 还是 1 对多（要点 1.1）

| 关系 | 类型 | 原型表现 |
|---|---|---|
| 群聊 → 成员（AI） | 1 对多 | 成员列表 / 卡片（右面板 + 成员卡） |
| 群聊 → 消息 | 1 对多 | 消息流列表（多站点徽章） |
| 成员 → 回复 | 1 对多 | 消息流中署名 + 回复计数 |
| 人员库 → 模板 | 1 对多 | 卡片网格列表（非表单） |
| 模板 → 使用记录 | 1 对多 | 卡片"已使用 N 次" |
| 新建 / 编辑（单个对象） | 1 对 1 | **表单弹窗**（画在主屏右侧） |

规则：一对多用**列表/卡片**展示，1 对 1 编辑用**表单**。列表页按"查询条件区 / 查询结果区 / 操作区"三段式绘制（要点 7）。

## 3. 元件用途表（要点 2：元件不能错用）

| 元件 | 唯一用途 | 禁止用法 |
|---|---|---|
| 按钮 Button | 触发动作（发送/新建/保存/删除） | 不做状态展示、不做装饰 |
| 站点徽章 Badge | AI 站点只读标识（色点+名称） | 不可点击、不承担动作 |
| 状态 pill | 对象当前状态（进行中/空闲/已连接） | 不用于动作 |
| 标签 tag | 可删除的属性标签（× 号） | 不用于状态 |
| 分段控件 segmented | 互斥选择（语言/主题/站点） | 不用于非互斥 |
| 开关 toggle | 布尔开关（外部智能体控制） | 不用于三态 |
| 进度条 | 执行进度 | 不用于装饰 |
| 卡片 card | 信息块容器（可含上述元件） | 卡片本身不可点击（点击走内部按钮） |
| 输入框 input | 文本录入 | 展示用文字不用输入框 |
| ⋯ 菜单 | 对象级操作（重命名/删除/复制） | 不替代主按钮 |

## 10. 弹窗绘制规则（要点 9）

- 所有弹窗（新建/编辑/删除确认/⋯菜单）画在**对应页面主屏右侧**，间距 **40**，独立顶层板。
- **禁止**全屏遮罩（scrim）覆盖主屏。
- 弹窗命名：`modal-<页面>-<动作>`（如 `modal-人员库-新建模板`）。
- 页面画布加宽容纳：顶层顺序（底→顶）= 主屏框 WA-* → 各弹窗板。

## 12. 图层顺序规范

1. 每页顶层（底→顶）：`WA-<页面>` 主屏框（1440×900）→ `modal-*` 弹窗板 → `note-*` 备注板。
2. 主屏框内子层顺序：按视觉从左到右 / 从上到下 append（flex 容器内 append 顺序 = 阅读顺序）。
3. 屏内浮层（编排状态面板、缩放控制）放在其父画布 children **最后**（最上层）。
4. **禁止**任何板覆盖主屏（无遮罩、无绝对定位压层）。
5. 命名：主屏 `WA-<页面>`；面板 `rail` / `sidebar` / `main` / `role-panel` / `topbar` / `canvas`；弹窗 `modal-*`；备注 `note-*`。
6. 页面顺序（按名称）：01 工作台 / 02 人员库 / 03 编排中心 / 04 设置与外部模型 / 05 架构总览 / 06 设计规范 / 07 UI客户端·Web-Agent / 08 UI客户端·opencode。

### ⚠ Penpot 插件 API 坐标陷阱（已踩坑，2026-09 修复）

- 本 MCP 插件环境里 **`shape.x / shape.y` 是页面绝对坐标**；`parent.appendChild(child)` 只改层级归属，**不平移坐标**。
- 因此往非原点板（x/y ≠ 0,0 的 modal/note 板）里放子元素时，必须直接传 **`板原点 + 局部坐标`** 的页面绝对值；若传局部值，内容会被画到页面左上角（板看起来"空的"）。
- 主屏板 WA-* 在 (0,0)，局部=绝对，不受影响。
- 修复方法：对每个非原点顶层板 B，遍历所有子孙 D：`D.x += B.x; D.y += B.y`（叶子形状无 `children`，遍历要 `(node.children || [])`）。
- 连接不稳定：标签页被挂起会断连且 **`storage` 随重连清空**，辅助库每次会话需重装；构建期间保持 Penpot 标签页前台。

## 17. Web Agent UI 客户端（Flutter 桌面端）原型规范

> 源码：`packages/web-agent-ui`（Flutter，Material 3，Windows 构建）。本客户端与 Chrome 扩展是**两个入口**：客户端通过本地 daemon（端口 19305）驱动扩展内的 AI 网页会话，同时内嵌 opencode 会话管理。

### 17.1 顶层双模式（HomeShell）

- AppBar：左 = 图标 + 模式名（"opencode" 或 "Web-Agent 模式"）；右 = **"Web-Agent 模式" 标签 + Switch**（默认 OFF = opencode 模式）。
- 全局快捷键：**Shift+End** 切回 opencode 模式；**End** 停止当前活动任务（两种模式各自 stop）。
- body：Switch ON → WindowsShell；OFF → OpencodeView。

### 17.2 Web-Agent 模式：窗口列表（WindowsShell）

| 区域 | 内容 |
|---|---|
| 左栏 220px | 标题"窗口"；窗口 tile（标题 + × 关闭，选中高亮 secondaryContainer）；底部"＋ 新建窗口"（tonal） |
| 主区 | 激活窗口 → ChatWindowView；无窗口 → 空态"没有打开的窗口" |

- 窗口默认标题 **"新窗口 N"**（N = 现有窗口数 + 1）；新建窗口自动激活。
- × 关闭窗口**无确认弹窗**（直接关）；关闭当前激活窗口自动切到最后一个窗口。
- 窗口 ↔ 扩展群聊**当前无绑定**（窗口只是并行对话容器）→ 待确认 #6。

### 17.3 聊天窗口（ChatWindowView）

从上到下：

1. **窗口头**：窗口标题 + 刷新按钮（重新探测 daemon 连接）。
2. **守护进程 banner（4 态，要点 3 全画）**：

| 状态 | 颜色 | 文案 |
|---|---|---|
| 检测中 | 灰 | 正在检测本地守护进程… |
| daemon 未运行 | 红 | 守护进程未运行，请先运行 tools/start-ui.ps1 启动 |
| 扩展未连接 | 橙 | 守护进程已连接，但 Web Agent 扩展未连接（请打开扩展并开启"本机智能体控制"） |
| 已连接 | 绿 | 已连接 daemon v{版本} · 挂起任务 {N} |

3. **对话轮次列表**（1 对多：一轮 = 1 用户消息 + N 条并行回复）：
   - 用户消息：右对齐气泡（primaryContainer）。
   - 并行回复（ParallelReplyView）：**1 个模型 = 1 列，≥2 个 = 2 列**卡片；卡 = 模型图标 + 模型名 + 状态（pending 转圈 / received 正常 / error 红）+ 正文。
   - 无回复时：spinner + "等待回复…"。
4. **模型栏（ModelBar）**：标签"模型" + 6 个 **FilterChip 多选**（DeepSeek/豆包/ChatGPT/Gemini/Claude/Grok）；点选即切换该窗口并行目标。
5. **输入区**：
   - 输入 `@` 弹出**模型建议卡**（按 id/name 过滤 6 模型，点选插入 @model）。
   - 输入框占位"输入消息，@模型 指定模型…"。
   - 运行中：红色"停止"按钮（stopTask）；发送中：主按钮内 spinner。
   - 发送语义：@ 的模型 + 模型栏选中的模型**全部并行**收到该消息。

### 17.4 opencode 模式（OpencodeView）

从上到下（左栏 220px + 主区）：

**左栏"会话"**：
- 服务器 banner（opencode 服务连接状态）。
- **只列顶层会话**；数量不一致时显示"共 N 个会话，显示 M 个顶层会话"。
- tile：标题 + 时间（今日 HH:MM / 其他 M/D HH:MM）+ 删除。
- 删除确认对话框（要点 6）："确认删除会话" + **"该会话下有 N 个子会话，将一并删除，无法恢复。"** + 若被终端占用追加警告 **"该会话可能正被 opencode 终端使用，删除将同时删除服务端会话。"** + 取消 / 删除（danger）。
- 底部"＋ 新建会话"。

**主区**：
1. 会话头：会话名 + **模型下拉（provider/model）** + 模型 pill + 刷新。
2. 消息流：用户右气泡 / 助手左气泡（含 modelLabel）；内容支持 **mermaid 代码块自动渲染成图**、文件引用 chip（点击预览）。
3. **确认卡堆栈（_ConfirmationStack，优先级 权限 > 问题 > Plan）**：
   - **权限卡（ConfirmWizard）**：标题"权限请求" + pattern 摘要；问题"允许此操作吗？"选项 **一次允许 / 总是允许 / 拒绝**（首个标"推荐"）+ 自己输入（附加说明）；**跳过 = 拒绝**。
   - **问题卡（ConfirmWizard）**：标题"选择确认" + "请依次回答以下 N 个问题"；每题一步（单选/多选 + 自己输入）；多题时确认按钮 = "提交全部"。
   - **Plan 卡**：Plan 模式常驻提示"当前处于 Plan 模式" + 说明 + **保持 Plan / 切到 Build 执行**。
4. 输入区：
   - `/` 弹**命令建议卡**（/命令 + 描述）。
   - **附件 chips**（文件/文件夹，可预览/移除）。
   - **外部占用 amber banner**："opencode 终端正在处理该会话，发送消息将提示是否接管"。
   - 行：＋附件 / 输入框（占位"输入消息，回车发送；输入 / 查看命令；Tab 切换 Plan/Build"）/ 停止（sending 时）或 发送。
   - 底行：**Plan/Build 切换 pill（Tab 键切换）** + 当前模型标签。

### 17.5 默认值 / 限制 / 元件（沿用第 3~6 节规则）

| 位置 | 字段 | 默认/限制 |
|---|---|---|
| 07 模式开关 | Web-Agent 模式 | 默认 OFF（opencode 模式） |
| 07 模型栏 | 并行模型 | 默认未选（空态提示"选择底部模型…"） |
| 07 窗口 | 标题 | "新窗口 N" |
| 08 确认向导 | 首个选项 | 恒定标"推荐" |
| 08 权限 | 跳过 | 等价"拒绝"（危险默认，需标注） |
| 08 Plan 卡 | 模式 | Plan 会话常驻，可切 Build |

元件用途（本客户端特有）：**FilterChip = 多选开关**（模型栏）；**Switch = 布尔**（模式开关）；**ConfirmWizard = 分步确认**（权限/问题，非自由表单）；**banner = 连接状态**（daemon/服务器/外部占用，不做动作）。
